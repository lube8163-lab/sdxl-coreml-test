# FLUX.3 CoreAI 実機性能の改善

2026-10-17〜18（UTC+07）の一連の計測を保存する。生レポートの日時はUTC。
物理 iPhone 17（iPhone18,3）/ iOS 27.0.1、Release の独立検証アプリを使用した。
512×512、固定キャプション、seed42、16ステップ。提出済みのFLUX.2アプリとは別の実験。

採用設定は、統合側28ブロックを8・8・8・4の四関数に結合して保持し、
画像側と文章側の関数は各回解放する構成。元のINT4定数、BF16計算、全層と順序を保持する。

同一の最終ビルドで、DiTは元の方式89.28秒、採用設定69.77秒（約21.8%短縮、約1.28倍）。
Qwen＋DiT＋VAEは94.60秒から75.45秒。ハッシュ確認・安全性確認・保存などを含む
プローブ開始〜保存は、秒単位の日時記録で103秒から85秒だった。
`phys_footprint` のサンプル最大は1.159GBから1.652GBへ増加する。
採用設定の先行実行も70.45秒で完走した。

全9回で16ステップ・入力確認・六視点の安全性確認・PNG保存を完了し、出力PNGが一致した。
SHA-256: `f71fb682f82e7c16d4eba4a3bfd43312637e9b8c12789f130f58eb9c923da674`。
単一キャプション・単一seedの結果であり、非量子化モデルとの品質比較や多条件評価ではない。

初期の元の方式は107.16秒だったが、後の同一ビルド計測は89.28秒になった。
OS・ランタイムのキャッシュはリセットしておらず、初期値との差をすべて変更の効果とは扱わない。
温度状態も各呼び出しに記録した。粗い温度状態が同じでも、同じGPU周波数を保証しない。
モデル生成・関数読み込み・推論awaitは壁時計時間であり、GPUカーネルだけの時間ではない。
50ms間隔のメモリサンプルは瞬間ピークや端末全体の消費量を保証しない。

全関数を保持した別条件では、読み込みを減らせても推論awaitが伸びたため採用していない。
Windows V100は32GB版とのユーザー申告のみで、SSH未設定。今回Windows上のジョブは実行していない。
