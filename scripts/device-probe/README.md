# Physical iPhone experiment

`prepare_phone_probe.py` creates a separate source copy outside the repository's iCloud folder. It preserves the shipping files, mandatory input/output safety and four-step 512px model. Its default bundle ID is `com.tasuku.sdxlcoremltest.iphone14probe` and display name is `ローカル画像生成 検証`. `--bundle-id` selects another isolated probe ID; the shipping bundle ID is rejected.

The current production source already uses a six-GB minimum, `AIModelAsset` summary metadata and Extended Virtual Addressing. Probe provenance reads the production threshold instead of hardcoding the historical eight-GB value. `--shipping-configuration` keeps the current guard, GPU runtime, retention and safety; the legacy driver still overrides the asset location to bundled verified files. `--metadata-summary` retains the current production lookup. `--transformer-cpu` selects the public CPU-only specialization in the isolated copy. The October 13/14 reports below describe their original source snapshots and remain unchanged.

For a test of the production configuration, add `--shipping-configuration`. This leaves the engine, original RAM guard, GPU runtime and warm policy unchanged; the view model uses a bundled test asset location, and cannot be combined with experimental runtime or entitlement options. Only the copied app's startup driver, appended assertions and bundle identity change. Provenance records source hashes and reports whether the copied engine/view-model prefix matches. The asset-location override means the view-model prefix differs from the downloaded-model shipping app. This run also exercises ordinary prompt preparation, warm repeat generation, changed prompts, the 30-second idle expiry and regeneration after the view model releases all resources.

Use a fresh destination; the preparation script refuses to overwrite prior experiments. Add `--reference-image /absolute/path/to/known-benign.png` to exercise all six real classifier views independently of FLUX execution.

Build the copied project for the intended device with normal development signing. Install that app through `devicectl`, then launch its bundle ID with `--console` and the `--device-smoke` argument. The test writes only its own `Documents/DeviceValidation` files, saves only classifier-approved images, and records its last stage before a native crash. It temporarily keeps its own screen awake and restores the idle setting on normal completion. Retrieve that exact app-data directory with `devicectl device copy from`.

For the memory-warning regression, pass both `--device-smoke` and `--memory-warning-smoke`. This runs one checked image and posts `UIApplication.didReceiveMemoryWarningNotification` from the main actor after a diffusion progress update. The notification follows the real app handler; it does not allocate artificial pressure or bypass safety. The test waits for the scheduled resource cleanup and records whether the image survives and the prepared state resets. Lifecycle logs distinguish these injected notifications from warnings observed in ordinary runs. Event logs append across launches; attribute each run using its report's start/end uptime range.

The 2026-10-13 iPhone 14 results are recorded in `review-notes/2026-10-13/iphone14-device-validation.json`: safety checks passed, Qwen ran after avoiding GPU metadata specialization, and none of the three configurations completed FLUX generation. The reference safety image is a prior checked Mac output, not an image generated on iPhone 14. A caught model error and a C++ abort are recorded separately.

## Six-GB retest instrumentation (2026-10-14)

The isolated driver now records footprint, RSS, process-lifetime footprint high-water mark and default-device Metal allocation on a 50 ms background queue, independent of main-actor progress callbacks. Read the CSV filename from `report.json`; actual maximum sample gaps are also reported. Counters overlap and must not be added.

`--keep-warm` lets the lower-guard copy use the ordinary retention/preparation policy. `--frequent-reshapes` implies metadata-summary lookup and sets Apple's public reshape-specialization hint on the transformer in the copied runtime only. This case still aborted during transformer loading on the tested iPhone 14. See `Experiments/FluxMemoryRetest/README.md` for the test matrix, Mac measurements, limits, common Bonsai comparison fixtures and optional allocation-request debugger commands.

The connected [2026-10-14 iPhone 14 retest](../../measurements/2026-10-14/iphone14-retest/README.md) failed in the baseline/summary/reshape cases, then completed five checked images with `--keep-warm --metadata-summary --extended-virtual-addressing`. This new option writes a probe-only entitlement file and sets signing on the isolated target. The explicit option is incompatible with `--shipping-configuration`, which now inherits the same entitlement from the production project; verify the entitlement in the signed app. It expands address space, without requesting increased physical-memory limits. Production files and model bytes remain unchanged.

The debugger script now targets only the actual `allocateResource` entry, excluding `deallocateResource` and thunks, and uses `--skip-prologue false` to preserve argument registers. Register values from deallocation are pointers, not requested sizes. The validated failure argument was 76.5 MiB; debugger runs are excluded from performance timing.

The memory-warning driver now waits up to sixty seconds for diffusion progress. Its earlier ten-second window expired during A15 model/function loading, even though the checked generation later succeeded. Read `memory-warning-injected` rather than treating the requested launch flag as proof that the warning happened. The later iPhone 14 regression injected at step 1, completed the same checked pixels and released prepared state. This is a test-driver change only.

When checking an App Store comparison app, add `--include-default-apps` to `devicectl device info apps`; the default listing contains only developer apps. Absence from that default listing does not establish that Bonsai Studio is uninstalled. The current release app is `com.prismml.image-studio`, version 0.4.0 / build 11. A generation result requires separately completing its model download and actually running it.
